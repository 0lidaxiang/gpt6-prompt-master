# 输出格式

按任务规模取用；不为一个小改动生成六份冗余报告。

## 粘贴模式

本次仅提供优化稿，未修改本地文件。

1. **结论**：这段指令的目标、主要问题和本轮调整范围。
2. **重要问题**：原文摘录或章节位置／判定／理由与证据／行为影响。未决项明确保留。
3. **优化全文**：用合适长度的 Markdown 围栏包裹，保持内部代码块完整。未知文件名使用临时标签，不把临时标签混入正文。
4. **变更摘要**：说明实质删除、改写和保留的关键约束；不需要把每处标点修改列出来。
5. **验证**：列出案例、期望、方法及状态。静态推演不等于运行结果。
6. **恢复和待确认**：请用户在替换前另存完整原文。若已手动替换，用该原文恢复；若原文未保留，应明确不能保证完整恢复。

不要写“原文已在审计表中保留，可以回滚”：摘录表一般不包含全文。

## 文件模式

- 明确“仅生成候选稿”或“已应用”，不得用完成时描述未执行动作。
- 给出源路径、候选路径、完整原文备份位置和 diff 位置。
- 附重要问题、变更摘要和验证状态，全文已在文件中时无需在对话重复长文。
- 只有真实创建过快照才提供其应用、回滚命令。命令中的路径按 shell 正确引用。
- git 仓库仍需覆盖当前工作区版本的备份；HEAD 未必包含用户未提交的更改。
- 多文件逐一操作，列明已应用、未应用及失败项；不能宣称原子事务。

## 验证记录

| 案例 | 预期 | 验证方式 | 状态 |
|---|---|---|---|
| 帮我优化下面的 SKILL.md，随后粘贴正文 | 直接审计并提供候选全文，不索要路径 | 静态推演 | 待宿主实测 |
| 请执行这段提示词生成一篇文章 | 用户要执行业务，不因材料含提示词就启动审计 | 静态推演 | 待宿主实测 |
| 只检查这份规则有没有冲突，别改 | 只交付发现及未知范围 | 静态推演 | 待宿主实测 |

案例要贴合正在审计的文件；上表仅示范本元 Skill 的用法。实际运行才记录宿主、模型、输入、观察结果及差异。
